# Project Rules

- Inspect relevant existing code before editing; make the smallest safe change.
- Preserve working behavior and unrelated code. Do not rewrite architecture without permission.
- Reuse the project's stack, conventions, and dependencies. Do not invent files, APIs, routes, tables, columns, or package behavior.
- For bugs, identify the likely root cause before editing.
- Validate untrusted input on the server; protect authorization, secrets, and sensitive data.
- Verify changes with the narrowest useful checks. Never claim a test passed unless it ran successfully.
- Explain important changes briefly in beginner-friendly language. Avoid lengthy explanations unless asked.
- Load a specialized Skill only when its description matches the task. Do not load unrelated Skills.
